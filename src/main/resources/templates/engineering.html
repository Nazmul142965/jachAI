One request, step by step

What happens between a click and the answer on screen.

  1. Browser sends

    A call to the API with the access token.

  2. Security filter

    Checks the token signature and expiry.

  3. Controller

    Validates the input and rejects bad requests early.

  4. Service

    Checks membership, role and plan limits.

  5. MongoDB

    Reads or writes. Every query includes the organization.

  6. Response

    A result, or an error that says what to do next, in your language.

Two flows worth knowing

The places where trusting the browser would be a mistake.

A payment

  • Created
  • Checkout ready
  • Verified
  • Applied

Only the server can move a payment forward. Coming back from the payment page grants nothing by itself. When a payment is applied, the plan is extended and a receipt is emailed. A cancelled payment stops the flow.

An AI request

  • Ask the first provider
  • Fails or too slow
  • Ask the second provider
  • Answer

If the first provider fails or takes more than 25 seconds, the second one answers instead. The daily limit is charged once, and a provider that keeps failing is skipped for two minutes.

Problems that changed the design

Each decision answers a failure we could point to.

Answers can arrive late or twice.

FixThe server sets the deadline, and submitting is safe to repeat.

One person has several roles.

FixRoles belong to an organization, and personal practice stays outside official scores.

Networks retry and providers disagree.

FixEmails, quotas and payments use unique ids, so a repeat never counts twice.

A browser redirect can lie.

FixA payment is applied only after the server confirms it with the provider.

AI can fail or be slow.

FixA second provider takes over automatically.

A stolen token is dangerous.

FixThe access token lives in memory. The renewal token is an HttpOnly cookie that works once.

One database query once stopped the whole app.

FixA derived sum over money failed at startup, so it became a hand-written aggregation.

Hard words lock people out.

FixEvery screen has plain English and Bangla, and errors say what to do next.

Run it yourself

Five steps from nothing to a working copy on your machine.

  1. Get the code

    Clone the repository.

    git clone https://github.com/Nazmul142965/jachAI.git

  2. Point it at MongoDB

    A local one works.

    $env:MONGODB_URI = "mongodb://localhost:27017"

  3. Start the demo

    One script starts it with demo roles.

    scripts/start-local.ps1 -Demo -Port 8102 -DatabaseName jachai_demo_ui

  4. Open it

    Visit port 8102 and choose a demo role.

    http://localhost:8102

  5. Run the tests

    Java first, then the browser journeys.

    ./mvnw test node src/test/frontend/run-journeys.js
